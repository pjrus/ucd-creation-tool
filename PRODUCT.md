# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

TanStack Start with React, TypeScript, Tailwind CSS, shadcn/ui, TanStack Router, SVG, ELK.js, and IndexedDB. Core functionality runs locally in the browser without a backend.

## Users

Software and product teams documenting system behaviour during discovery, design, technical planning, and stakeholder review.

## Product Purpose

Turn readable Markdown-like source into correct UML use case diagrams immediately. Success means a user can describe actors, system boundaries, use cases, and relationships faster than with general-purpose diagram syntax while retaining a standards-aware SVG result.

## Positioning

The product is a focused, local-first UCD workbench: a compact domain syntax and live UML preview instead of a general diagramming language or manual drawing canvas.

## Operating Context

Users work in a split editor while discussing requirements, refining scope, and sharing diagrams. Source files and SVG or PNG exports must remain portable, while local diagrams autosave without accounts or network services.

## Capabilities and Constraints

- Parse actors, use cases, system boundaries, associations, include, extend, and generalisation relationships.
- Keep parser, validation, layout, rendering, storage, and export concerns independent.
- Render standards-aware UML geometry as interactive SVG.
- Provide useful source-line errors, automatic layout, zoom, pan, fit, local autosave, diagram management, import/export, examples, and light/dark themes.
- Use flat colours only, with no gradients or decorative visual effects.
- Keep the MVP browser-local and avoid authentication, remote databases, and unnecessary backend infrastructure.

## Evidence on Hand

The supplied reference syntax establishes the canonical initial grammar. No external brand assets, commercial claims, or user research artefacts were supplied.

## Product Principles

- Make diagram intent readable in source form.
- Keep UML semantics correct and visible.
- Respond immediately while users type.
- Store work locally and keep it portable.
- Prefer modular, replaceable technical boundaries.

## Accessibility & Inclusion

The editor must support keyboard operation, visible focus, readable status and error messaging, sufficient contrast, reduced motion preferences, and responsive use on smaller screens.
